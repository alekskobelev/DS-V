# 🌐 Доступ к нейросетям из России: рабочие DNS (2026), DoH и прокси

Практическая инструкция для ситуации «нейросеть пишет: сервис недоступен в вашем регионе».
Актуальность данных: **октябрь 2026**. Адреса у сервисов меняются часто — перед настройкой
сверяйтесь с официальными страницами, ссылки в разделе 9.

---

## 1. Что важно знать в 2026 году

Классический совет «поставь `1.1.1.1`» **больше не работает**. Ситуация изменилась в августе 2026:

| Сервис | Открытый DNS (UDP/53) | DoH / DoT | Вывод |
| :--- | :--- | :--- | :--- |
| Cloudflare `1.1.1.1` | ❌ перехватывается на ТСПУ и уходит на резолверы НСДИ | ❌ TLS-сессия рвётся на ClientHello | не работает |
| Google `8.8.8.8` / `dns.google` | ❌ перехват | ❌ обрыв на старте шифрования | не работает |
| Quad9 `9.9.9.9` | ⚠️ у части операторов | ❌ `dns.quad9.net` режется по SNI | не работает |
| AdGuard `94.140.14.14` | ⚠️ | ❌ `dns.adguard-dns.com` режется по SNI | не работает |
| OpenDNS, NextDNS, DNS.SB | ⚠️ | ❌ | не работает |

Механика двух уровней:

* **открытый DNS по UDP/53** — оборудование ТСПУ распознаёт запрос и переписывает адрес получателя
  на резолвер НСДИ (`195.208.5.1` / `195.208.4.1`). Внешне всё «работает», но заблокированные домены
  получают `NXDOMAIN`, а все ваши запросы видит государственный резолвер;
* **DoH/DoT** — соединение устанавливается, но обрывается на этапе TLS: DPI распознаёт
  `dns.google`, `cloudflare-dns.com`, `dns.quad9.net`, `dns.adguard-dns.com` по имени в SNI.

Поэтому в РФ сейчас работают не «обычные публичные DNS», а **Smart DNS** — сервисы, которые
для доменов нейросетей возвращают адрес своего прокси-узла за пределами санкционных территорий.

### Чем Smart DNS отличается от обычного

```
Обычный DNS:  ваш ПК → «где gemini.google.com?» → 142.250.x.x (Google) → Google видит IP из РФ → отказ
Smart DNS:    ваш ПК → «где gemini.google.com?» → IP узла сервиса → узел передаёт TLS дальше,
                                                     не расшифровывая → Google видит ЕС → работает
```

Ключевое: сертификат остаётся подлинным (вендора), прокси не расшифровывает трафик, но **видит,
к каким доменам вы обращаетесь**. Это не VPN: через узел идёт только трафик из закрытого списка
AI-доменов, остальное — напрямую.

> ⚠️ Smart DNS лечит **только гео-блокировки самих вендоров** (Google, OpenAI, Anthropic).
> Блокировки Роскомнадзора он не обходит — для этого нужен VPN/прокси.

## 2. Быстрый вариант: одна ссылка в браузере

Если нужно «вставил и заработало» на одном компьютере — включите DoH в браузере и вставьте
адрес одного из сервисов ниже. Ничего устанавливать не нужно.

### 2.1. Адреса, которые вставляются в браузер

| Сервис | DoH-ссылка для браузера | Что открывает | Состояние (окт. 2026) |
| :--- | :--- | :--- | :--- |
| **DNS-AI** | `https://dns.dns-ai.ru/dns-query` | все основные нейросети (Gemini, Claude, Grok, Copilot) | ✅ работает, бесплатно, без регистрации |
| **GeoHide** | `https://geohide.ru/dns-query` | Gemini, ChatGPT, Claude, Grok | ✅ работает; российский узел нестабилен — используйте европейский |
| **Comss.one** | `https://dns.comss.one/dns-query` | Gemini, ChatGPT, Copilot, Claude, Grok | ⚠️ работает, но Gemini иногда упирается в капчу Google |

Рекомендуемый порядок перебора: **DNS-AI → GeoHide → Comss.one**.
Если один не отвечает — переключитесь на следующий, это занимает 20 секунд.

> ⚠️ Вставлять нужно именно **URL вида `https://…/dns-query`**, а не IP-адрес.
> Поле «Свой» в браузере принимает только HTTPS-шаблон DoH.

### 2.2. Chrome / Edge / Яндекс Браузер / Opera

1. Откройте `chrome://settings/security` (Edge: `edge://settings/privacy`, Яндекс: `browser://settings/security`).
2. Блок **«Использовать безопасный DNS»** (Use secure DNS).
3. Выберите **«Свой» / «Custom»** — не «Текущий сервис-провайдер».
4. Вставьте `https://dns.dns-ai.ru/dns-query`.
5. Перезапустите браузер.
6. Сбросьте кэш: `chrome://net-internals/#dns` → **Clear host cache**, затем
   `chrome://net-internals/#sockets` → **Flush socket pools**.

### 2.3. Firefox

1. `Настройки → Приватность и защита`.
2. Блок **«Включить DNS через HTTPS»** → **«Максимальная защита»** (иначе Firefox молча
   откатится на обычный DNS при первом сбое).
3. «Использовать провайдера» → **«Свой»** → `https://dns.dns-ai.ru/dns-query`.
4. Перезапустите браузер.

### 2.4. Safari / iPhone / iPad

Своей настройки DoH в Safari нет — устанавливается системный профиль:

1. Откройте в **Safari** → `https://dns-ai.ru/dns-ai.mobileconfig` (или `https://geohide.ru/`).
2. `Настройки → Профиль загружен → Установить` → код-пароль → **Установить**.
3. Проверка: `Настройки → Основные → VPN и управление устройством → DNS` → выбран нужный профиль.

Профиль помечается как «Не проверен» — это нормально для профиля без подписи компании.

### 2.5. Проверка, что включилось

```bash
# Должен вернуться IP прокси-узла сервиса, а не адрес Google
dig +short gemini.google.com @194.87.196.13
```

Или в браузере: откройте нужную нейросеть в **режиме инкогнито** (чтобы исключить кэш и куки).
Если появилась ошибка региона — смените сервис из таблицы в 2.1.

## 3. Настройка на уровне системы и роутера

Браузерный DoH закрывает **только браузер**. Приложения (десктопный ChatGPT, мобильный Gemini,
IDE, консольные утилиты) продолжат ходить через DNS провайдера — и упираться в ту же ошибку.
Поэтому надёжнее настроить систему.

### 3.1. Windows 11

`Параметры → Сеть и Интернет → Wi-Fi (или Ethernet) → Свойства оборудования → Назначение DNS-сервера → Изменить`

* IPv4: **Вкл.**, предпочтительный `194.87.196.13`, альтернативный `45.151.102.219`
* «DNS через HTTPS»: **Вкл. (шаблон вручную)** → `https://dns.dns-ai.ru/dns-query`
* «Возврат к открытому тексту»: **Выкл.**

Обязательно заполните и раздел **IPv6** тем же шаблоном — иначе Windows продолжит часть запросов
пускать по IPv6 мимо выбранного резолвера. После сохранения рядом с адресами должна появиться
метка **«Зашифровано»**.

```powershell
ipconfig /flushdns
```

### 3.2. Android

`Настройки → Сеть и интернет → Частный DNS-сервер → Имя хоста провайдера` → `dns.dns-ai.ru`

В это поле вводится **только имя**, IP-адрес там не работает. Настройка действует на все
приложения и на Wi-Fi, и на мобильную сеть.

### 3.3. Роутер (Keenetic, MikroTik, OpenWrt)

Один раз — и закрыта вся сеть, включая телевизоры и устройства без поддержки DoH.

```
DoH:  https://dns.dns-ai.ru/dns-query
DoT:  dns.dns-ai.ru
```

MikroTik RouterOS 7:

```
/ip dns set use-doh-server="https://dns.dns-ai.ru/dns-query" verify-doh-cert=yes
```

### 3.4. Linux / сервер портала

`systemd-resolved` умеет DoT (не DoH), и этого достаточно:

```bash
sudo mkdir -p /etc/systemd/resolved.conf.d
sudo tee /etc/systemd/resolved.conf.d/99-ai-dns.conf >/dev/null <<'EOF'
[Resolve]
DNS=194.87.196.13#dns.dns-ai.ru 45.151.102.219#dns.dns-ai.ru
DNSOverTLS=yes
Domains=~.
EOF
sudo systemctl restart systemd-resolved
resolvectl status | grep -A2 "Current DNS Server"
```

Имя после `#` обязательно: по нему проверяется сертификат, и без него соединение не установится.
`DNSOverTLS=yes` — именно `yes`, а не `opportunistic`: открытый 53-й порт у таких сервисов закрыт,
и «оппортунистический» режим тихо оставит сервер вообще без DNS.

**Почему это важно для портала:** `server.ts` обращается к `generativelanguage.googleapis.com`.
С российского IP Google отвечает отказом по региону независимо от ключа `GEMINI_API_KEY`.
Smart DNS на уровне сервера решает это тем же способом, что и на рабочей станции, — запрос уходит
через внешний узел сервиса. Альтернатива — свой релей (см. 5.3).

### 3.5. Docker

Контейнеры **не наследуют** DNS хоста. Пропишите в `/etc/docker/daemon.json`:

```json
{ "dns": ["194.87.196.13", "45.151.102.219"] }
```

```bash
sudo systemctl restart docker
docker run --rm alpine cat /etc/resolv.conf   # проверить, что применилось
```

Или точечно в `docker-compose.yml`:

```yaml
services:
  app:
    dns:
      - 194.87.196.13
      - 45.151.102.219
```

> ⚠️ Через Docker DNS передаётся только обычный UDP/53. Если выбранный сервис открытый DNS
> не отдаёт (DNS-AI закрывает 53-й порт), контейнеру нужен DoT-клиент
> (`dnscrypt-proxy` / `cloudflared`) либо прокси — см. раздел 5.

## 4. Что Smart DNS не лечит

| Симптом | Причина | Что делать |
| :--- | :--- | :--- |
| OpenAI: «Country not supported» даже с DNS | двойная блокировка: и РКН, и сам OpenAI по IP + проверка номера телефона | Smart DNS не поможет — нужен VPN с резидентным IP или агрегатор с оплатой в рублях |
| Gemini: пускает, но просит капчу / «недоступен в аккаунте» | регион зашит в Google-аккаунте (`policies.google.com/country-association-form`) | сменить страну аккаунта или завести новый; иногда помогает режим инкогнито |
| Сайт открылся, но оплата не проходит | блокировка по BIN-коду российской карты | иностранная карта или посредник; DNS тут ни при чём |
| Ничего не открывается, интернет «частично умер» | включён только DoH без запасного резолвера, а сервис не отвечает | добавить альтернативный DNS или временно вернуть «Автоматически» |
| Приложение не работает, а сайт в браузере работает | настройка применена только к браузеру | раздел 3 — настройка на уровне ОС/роутера |

## 5. Если DNS не помог: прокси для исходящих вызовов ИИ

Когда нужен гарантированный канал (сервер, CI, боевой портал) — прокси надёжнее Smart DNS.

### 5.1. Проверка через прокси

```bash
curl -x http://USER:PASS@PROXY_HOST:3128 -sS -o /dev/null -w '%{http_code}\n' \
  https://generativelanguage.googleapis.com/v1beta/models
```

### 5.2. systemd-юнит портала

```ini
[Service]
Environment=HTTPS_PROXY=http://PROXY_HOST:3128
Environment=HTTP_PROXY=http://PROXY_HOST:3128
Environment=NO_PROXY=localhost,127.0.0.1,.internal
```

### 5.3. Node.js: важный нюанс

Встроенный `fetch` (undici) **не читает** `HTTP_PROXY`/`HTTPS_PROXY` автоматически.
Для серверных вызовов Gemini нужен явный диспетчер:

```ts
import { ProxyAgent, setGlobalDispatcher } from 'undici';

if (process.env.HTTPS_PROXY) {
  setGlobalDispatcher(new ProxyAgent(process.env.HTTPS_PROXY));
}
```

Альтернатива — собственный релей: Cloudflare Worker или VPS в ЕС, который проксирует
`generativelanguage.googleapis.com`, а портал ходит на него по своему домену.

### 5.4. Полностью локальный вариант

Если внешний канал нестабилен, ИИ-функции портала можно перевести на модели, работающие из РФ:
YandexGPT (`llm.api.cloud.yandex.net`), GigaChat (`gigachat.devices.sberbank.ru`).

## 6. Диагностика за 6 команд

```bash
# 1. Что отдаёт выбранный Smart DNS для домена нейросети
dig +short gemini.google.com @194.87.196.13

# 2. Что реально использует система
getent hosts gemini.google.com

# 3. Не перехвачен ли открытый DNS (ответ придёт с 195.208.5.1 = НСДИ)
dig +short ya.ru @8.8.8.8

# 4. Проверка TLS/HTTP до API
curl -sS -o /dev/null -w 'connect=%{time_connect} tls=%{time_appconnect} code=%{http_code}\n' \
  https://generativelanguage.googleapis.com/v1beta/models

# 5. Проверка ключа (ожидается 401/403, но не таймаут)
curl -sS -H "x-goog-api-key: $GEMINI_API_KEY" \
  'https://generativelanguage.googleapis.com/v1beta/models?pageSize=1' | head -c 300

# 6. Полный трейс TLS
curl -v --max-time 15 https://generativelanguage.googleapis.com/v1beta/models 2>&1 | tail -30
```

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `dig @8.8.8.8` отвечает с `195.208.5.1` | перехват DNS на ТСПУ | раздел 2/3 — Smart DNS вместо публичного |
| Резолвится, но `curl` висит на `time_appconnect` | DPI по SNI либо блок по IP | прокси (раздел 5) |
| `403` с телом про регион | гео-ограничение вендора | Smart DNS (раздел 2) или прокси |
| `401`/`400` | сеть в порядке, проблема в ключе/квоте | проверить `GEMINI_API_KEY` и лимиты |

## 7. Безопасность и риски

* **Smart DNS видит ваши домены.** Прокси не расшифровывает TLS, но список посещаемых AI-доменов
  ему известен. Не используйте случайные сервисы из форумов.
* **Не routing, а подмена адреса.** Если сервис закроется или сменит адреса — «интернет умрёт»
  целиком. Всегда держите альтернативный DNS вторым.
* **Одного DNS мало для аккаунтов.** OpenAI и Google дополнительно проверяют регион аккаунта,
  номер телефона и BIN карты — это DNS не меняет.
* **Юридический аспект.** Ст. 13.53 КоАП РФ предусматривает ответственность за поиск и доступ
  к материалам из федерального списка экстремистских с использованием средств обхода блокировок.
  Решение о применимости принимает организация, а не администратор DNS.

## 8. Чек-лист администратора

1. Определите реальную причину: `dig` + `curl` (раздел 6), а не «на глаз».
2. Для одного пользователя — DoH в браузере (раздел 2).
3. Для рабочих мест и приложений — настройка ОС или роутера (раздел 3).
4. Для сервера портала — DoT через `systemd-resolved` **плюс** резервный прокси в `server.ts`.
5. В Docker прописан `dns` — иначе контейнеры ходят мимо настроек хоста.
6. Секреты (`GEMINI_API_KEY`) только в `.env`/секретах платформы, не в репозитории.
7. Раз в месяц сверяйте адреса на официальных страницах — они меняются.
