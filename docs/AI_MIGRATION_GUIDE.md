## 🏗 1. Глубокая архитектура и технологический стек

Проект представляет собой монорепозиторий, совмещающий Frontend (SPA) и Backend (Express API) в единой инфраструктуре с гибридным подходом к хранению данных.

### Стек технологий:
- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS, Lucide Icons.
- **Backend:** Node.js (Express), порт 3000 (`0.0.0.0:3000`).
- **База данных:** PostgreSQL 17 (образ `postgres:17-alpine`), Drizzle ORM (семейство `pg`).
- **3D-Графика:** Three.js, React-Three-Fiber, Drei (просмотрщик CAD и GD&T тепловых карт).
- **Анимации и Графики:** motion/react, Recharts (для `CrmDashboard.tsx`).

### Особенности развертывания (server.ts):
- Backend и Frontend раздаются с одного порта (3000).
- В режиме разработки (dev) Vite подключается как middleware к Express.
- В режиме production (`NODE_ENV === 'production'`) Express раздает статику из папки `dist`.
- API-маршруты строго префиксируются `/api/*` (например, `/api/text-constants`, `/api/leads`).

## 💾 2. Архитектура данных и СУБД

### Гибридное хранилище (Fallback-механизм):
Система спроектирована с учетом максимальной отказоустойчивости промышленного сектора:
1. **Primary Database (PostgreSQL 17):** Основное хранилище через Drizzle ORM.
2. **Fallback Database (JSON/In-Memory):** Если БД недоступна, сервер автоматически переключается на чтение/запись в файлы `data/*.json` (например, `data/notificationSettings.json`), обеспечивая бесперебойную работу CRM и приема заявок.

### Ключевые сущности (Схема данных):
1. **`text_constants` (Глобальные тексты сайта):**
   - Таблица в PostgreSQL для хранения текстов (title, description, button labels).
   - *Поля:* `id`, `key` (уникальный ключ, напр. `home.hero.title`), `value`, `category`, `updated_at`.
   - *Интеграция:* При загрузке `<AppProvider>` запрашивает `/api/text-constants`, кэширует в `SiteTextsData` и отдает через `getText(key, fallback)`.

2. **`deals` & `commercial_proposals` (B2B CRM PRO):**
   - Хранение сделок по воронкам (`equipment`, `services`, `support`).
   - Поддержка мультивалютности (RUB, USD, EUR, CNY) и расчет НДС 22% (3 пункта: Без НДС, В т.ч. НДС, Итого с НДС).
   - Расчет вероятностей (Win Rate) для взвешенного прогноза.

3. **`service_requests` (Тикеты и Лиды):**
   - Входящие запросы с формы контактов, калькулятора, онлайн-чата и B2B портала.
   - Жесткий SLA (таймеры ответа 10-15 минут на обратный звонок).

## 🤖 3. Двойная система оповещений (МАКС-бот и Telegram)

В проекте реализован мульти-шлюз `src/server/notificationModule.ts` для параллельной отправки критических заявок менеджерам.

### Российский мессенджер МАКС (МАКС-бот):
Используется как защищенный корпоративный канал для дежурных инженеров.
- **Переменные:** `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `MAX_WEBHOOK_URL`, `MAX_API_URL`.
- **Функционал:** API Bot отправка (`/v1/messages`), защищенные вебхуки для внутренних сетей.

### Telegram Bot API:
Резервный/оперативный канал.
- **Переменные:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

### Логика (dispatchManagerNotification):
Каждый лид с сайта параллельно уходит в:
1. Telegram (если настроен).
2. Мессенджер МАКС (если настроен).
3. Корпоративную почту (`info@ds-enginering.ru`).
4. UI Pop-up с синтезом аудиосигнала (на экране оператора в CRM).

## 📊 4. Ключевые бизнес-модули платформы

1. **Инженерный дашборд CRM (`CrmDashboard.tsx`)**:
   - Обзор 30-летней истории бизнеса (1994-2026).
   - Графики Recharts: `Total Pipeline Value` (Сумма активных сделок и взвешенный пайплайн), `Lead Conversion Rate` (Конверсия этапов).
   - Таблица `Recent Requests` с SLA-индикацией и быстрыми переходами.
2. **Парк приборов и Метрология**:
   - Учет физических СИ (координатно-измерительные машины, трекеры).
   - Реестр метрологических отчетов (валидация погрешностей ГОСТ, экспорт в Excel).
3. **Интерактивный 3D-просмотрщик (WebGL)**:
   - Парсинг CAD-форматов в Three.js.
   - Визуализация GD&T отклонений (тепловые карты поверх сетки деталей).

## 🔐 5. Секреты и Переменные окружения

Все секретные ключи передаются исключительно через переменные окружения и не хранятся в коде (смотри `.env.example`).
- **База данных:** `SQL_PASSWORD` (или `DB_PASSWORD` / `POSTGRES_PASSWORD`), опционально `SQL_ADMIN_PASSWORD`.
- **Мессенджер МАКС:** `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `MAX_WEBHOOK_URL`.
- **Telegram:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- **ИИ / Нейросети:** `GEMINI_API_KEY` (внедряется платформой AI Studio).
- **Аналитика:** `VITE_YANDEX_METRICA_ID` (публичный фронтенд ключ).
- **Email-уведомления:** `ALERT_EMAIL_RECIPIENTS` (для рассылки SLA).

## 🛑 6. СТРОГИЕ ПРАВИЛА РАЗРАБОТКИ (AGENTS.MD)

Это фундаментальные законы проекта. Их нарушение недопустимо.

1. **Документирование каждого шага:**
   После любого добавления функционала, правки структуры или изменения БД, ИИ-ассистент **ОБЯЗАН** обновить:
   - `docs/SITE_PASSPORT.md` — инкремент версии, фиксация добавленных модулей.
   - `docs/USER_MANUAL.md` — добавление новых разделов о том, как пользоваться новой фичей.
   - `docs/CHANGELOG.md` — дата, версия, детальный список изменений.
   - `docs/DATABASE_DEPLOYMENT.md` — при изменении схемы Drizzle или `text_constants`.
   - `docs/README.md` и корневой `README.md`.

2. **Чистота корневой директории (Root Cleanliness):**
   В корне проекта (`/`) должны лежать **ТОЛЬКО** базовые конфиги (`package.json`, `vite.config.ts`, `server.ts`, `.env.example`, `docker-compose.yml`, `AGENTS.md` и т.д.).
   *КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТСЯ* сохранять в корне временные скрипты миграций (`migrate.js`, `patch.sh`, `test.py`). Все скрипты идут в `scripts/`, данные в `data/`.

3. **Иконки:** 
   Разрешено использовать ТОЛЬКО `lucide-react`. Запрещено рисовать иконки через SVG вручную.

4. **Интерфейс:**
   Русский язык, строгий промышленно-инженерный B2B Tone of Voice («ДС-Инжиниринг»).
