## 1. Введение и цели тестирования

### 1.1. Назначение документа
Настоящий документ регламентирует цели, стратегию, объем, график и порядок выполнения сквозного регрессионного тестирования программного комплекса компании **«ДС-Инжиниринг»**. 

### 1.2. Главные цели регрессии
1. **Предотвращение регрессионных дефектов**: Гарантировать, что добавление нового функционала (например, управление конфигураторами СИ в CMS `CmsConfiguratorsTab.tsx`, 3D Solid CAD визуализатор детали `PartVisualizer3D.tsx`, B2B ROI калькулятор) не нарушает работу ранее внедренных модулей (каталог ПО TopSolid/PolyWorks, воронка CRM, генерация ТКП в PDF, реестр договоров и парка СИ).
2. **Обеспечение целостности интеграций**: Проверка непрерывной сквозной передачи данных: *Калькуляторы / Конфигуратор СИ ➔ REST API ➔ СУБД PostgreSQL 17 / Fallback ➔ CRM-сделки ➔ Личный кабинет заказчика*.
3. **Контроль соответствия ГОСТ и стандартам точности**: Валидация математических алгоритмов расчета полей допусков (IT5–IT12), запаса точности $T/\text{MPE}$ по ГОСТ Р ИСО 1101 / ISO 10360 и формул окупаемости.
4. **Безопасность и отказоустойчивость**: Проверка защиты от CSRF (64-char hex token), валидации входящих схем JSON Schema Draft-07 (Ajv) и бесшовного переключения на дисковый fallback при сбоях СУБД.

## 5. Управление тестовыми данными и автоочистка (Teardown)

Для исключения загрязнения продуктивной базы данных регрессионный тестовый комплекс соблюдает следующие правила:
1. Все тестовые записи именуются с уникальным префиксом `TEST_REGRESSION_[TIMESTAMP]`.
2. В скрипте `scripts/test_crm_cms_integration.ts` реализован блок **Teardown Cleanup**: после прогона проверок все созданные сделки, контакты, ТКП, договоры и сессии чата удаляются из PostgreSQL и fallback-файлов.
3. Перед запуском тестов сохраняется резервный снимок `cms_store`.

## 6. Регламент и критерии готовности (Definition of Done)

### 6.1. События запуска регрессионного тестирования
- **Pre-Commit / Pre-Push**: Обязательный запуск `npm test` и `npm run lint` перед внесением изменений в репозиторий.
- **Релизная верификация**: Прогон полного пакета 84 проверок (63 Vitest + 21 сквозная проверка) перед публикацией релиза.
- **Обновление документации**: Синхронизация `docs/SITE_PASSPORT.md`, `docs/USER_MANUAL.md`, `docs/CHANGELOG.md` и `docs/TEST_REPORT.md` в соответствии с `AGENTS.md`.

### 6.2. Критерии успешного завершения (Exit Criteria)
- **Прохождение тестов:** 100% успешных проверок (0 провалов).
- **Сборка:** `npm run build` завершается с кодом возврата 0.
- **Отчет:** Сгенерирован актуальный `docs/TEST_REPORT.md`.
