## 1. Классификация дефектов (Severity & Priority)

### 1.1. Градация критичности дефекта (Severity)

| Уровень | Обозначение | Описание и критерии | Пример |
| :--- | :--- | :--- | :--- |
| **S1: Blocker** | 🔴 Блокирующий | Полная недоступность платформы, сбой запуска СУБД/сервера, падение процесса сборки, невозможность оформить заявку/заказ. | Сбой компиляции Vite `npm run build`, падение пула PostgreSQL без fallback. |
| **S2: Critical** | 🟠 Критический | Нарушение ключевой инженерной бизнес-логики, искажение метрологических расчетов или формул окупаемости ROI, утечка данных. | Ошибка в формуле запаса точности $T/\text{MPE}$ (ложное забракование), сбой CSRF-валидации. |
| **S3: Major** | 🟡 Значительный | Некорректная работа отдельного компонента при сохранении общей работоспособности системы; есть обходной путь (Workaround). | Сбой переключения ракурса камеры в 3D-просмотрщике `PartVisualizer3D`, зависание фильтра брендов. |
| **S4: Minor** | 🟢 Незначительный | Мелкие визуальные дефекты, ошибки верстки на нестандартных экранах, опечатки в статических текстах. | Небольшое смещение бейджа на смартфонах `<360px`, неточный перевод технического термина. |
| **S5: Trivial** | ⚪ Тrivial | Пожелания по улучшению эргономики, микроанимаций или форматированию документации. | Добавление плавной тени при наведении на карточку прибора. |

---

### 1.2. Градация приоритета исправления (Priority)

- **P1 (Urgent / Срочно):** Исправление в рамках текущего хотфикса (Hotfix), выпуск в течение 2–4 часов.
- **P2 (High / Высокий):** Исправление в рамках текущей итерации/спринта до релиза.
- **P3 (Medium / Средний):** Плановое исправление в следующем запланированном релизе.
- **P4 (Low / Низкий):** Устранение по мере высвобождения ресурсов (Backlog).

## 4. Примеры заполненных инженерных отчетов

### Пример 1: Дефект расчета температурной поправки при цеховом контроле

```markdown
### [BUG-MET-042] Некорректный учет температурного расширения стали при выборе среды «Цех (±5°C)»

- **Модуль / Компонент:** `MetrologyEquipmentConfigurator.tsx`
- **Версия системы:** v2.9.185-PROD
- **Критичность (Severity):** S2 - Critical
- **Приоритет (Priority):** P1 - Urgent
- **Окружение:** Google Chrome 128 (Windows 11, десктоп 1920x1080)
- **Роль:** Инженер-метролог (публичный доступ)

---

#### 1. Описание проблемы
При выборе производственной среды «Цех (±5°C)» для крупногабаритной детали из конструкционной стали ($L = 1500$ мм) расчетная погрешность измерения не учитывает температурную составляющую $\Delta L = L \cdot \alpha \cdot \Delta T$, в результате чего коэффициент запаса точности $T/\text{MPE}$ завышается на 35%.

#### 2. Шаги для воспроизведения
1. Открыть «Метрологический конфигуратор оборудования СИ».
2. На Шаге 1 установить длину $L = 1500$ мм, материал «Конструкционная сталь».
3. На Шаге 2 выбрать квалитет IT7 ($T = 40$ мкм).
4. На Шаге 3 выбрать среду «Цех (+28°C / градиент 5°C)».
5. Перейти на Шаг 4 и проверить формулу MPE.

#### 3. Фактический результат
Формула MPE отображает базовое лабораторное значение $\text{MPE} = 2.5 + 3.0 \cdot L / 1000 = 7.0$ мкм. Температурная погрешность $\approx 14.4$ мкм проигнорирована. Статус ошибочно показывает «Оптимально (Запас 5.7)».

#### 4. Ожидаемый результат
При цеховых колебаниях $\Delta T = 8^\circ\text{C}$ к MPE должна добавляться температурная неопределенность по ГОСТ ISO/TR 16015:
$$\text{MPE}_{\text{цех}} = \text{MPE} + L \cdot \alpha_{\text{сталь}} \cdot \Delta T = 7.0 + 1500 \cdot 1.2\times 10^{-5} \cdot 8 \cdot 1000 = 7.0 + 14.4 = 21.4 \text{ мкм}$$
Запас точности должен составлять $K = 40 / 21.4 \approx 1.87$ с выдачей предупреждения: «Требуется термоконстантная лаборатория ЦЗЛ».

#### 5. Диагностические данные
- Консоль чистая (логических исключений нет).
- Файл: `MetrologyEquipmentConfigurator.tsx`, функция `calculateMpeWithEnvironment()`.
```

### Пример 2: Сбой инициализации Three.js контекста на старых мобильных видеочипах

```markdown
### [BUG-3D-019] Ошибка создания WebGL 2.0 контекста в PartVisualizer3D на устройствах без аппаратного FP-шейдинга

- **Модуль / Компонент:** `PartVisualizer3D.tsx`
- **Версия системы:** v2.9.185-PROD
- **Критичность (Severity):** S3 - Major
- **Приоритет (Priority):** P2 - High
- **Окружение:** Мобильный планшет цехового мастера (Android 10, Mali-G52, Chrome 118)

---

#### 1. Описание проблемы
При открытии Шага 1 конфигуратора на устройствах со слабыми встроенными видеокартами или планшетах без поддержки WebGL 2.0 область 3D-просмотра отображает черный экран вместо твердотельной CAD-модели.

#### 2. Шаги для воспроизведения
1. Открыть конфигуратор оборудования на планшете с GPU Mali-G52.
2. Просмотреть область 3D-визуализации на Шаге 1.

#### 3. Фактический результат
3D-модель не отображается, в консоли браузера:
`THREE.WebGLRenderer: Error creating WebGL context: WebGL 2.0 not supported.`

#### 4. Ожидаемый результат
Компонент `PartVisualizer3D` должен автоматически выполнять graceful fallback на стандартный WebGL 1.0 рендерер, либо выводить информативную векторную 2D-схему детали с габаритными стрелками без сбоя остального интерфейса.

#### 5. Диагностические данные
- Затронутый файл: `src/components/metrology/PartVisualizer3D.tsx`, метод инициализации `new THREE.WebGLRenderer({ antialias: true })`.
```
