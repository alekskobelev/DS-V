# 🧪 СТРАТЕГИЯ, РЕГЛАМЕНТ И АВТОМАТИЗАЦИЯ ТЕСТИРОВАНИЯ «ДС-ИНЖИНИРИНГ»

> **Единая тестовая документация и инфраструктура непрерывного контроля качества (Quality Assurance & Regression Testing System)** для корпоративно-инжинирингового портала ООО «ДС-Инжиниринг».

---

## 1. Концепция и цели системы тестирования

Главная цель тестовой системы — **гарантировать 100% надежность и отказоустойчивость** бизнес-критичных модулей портала без необходимости ручного написания новых тестов при каждом обновлении кода:
1. **Автоматический прогон сквозных регрессионных тестов** в 1 клик (`npm test` / `npm run test:all` / `npm run test:unit`).
2. **Мгновенное формирование отчетов о тестировании** в машиночитаемом (`data/last_test_report.json`) и человекочитаемом формате (`docs/TEST_REPORT.md`).
3. **Безопасная автоочистка (Teardown Cleanup)** — тестовые данные создаются в изолированной песочнице и удаляются сразу после завершения проверок, не замусоривая продакшн-базу СУБД.
4. **Валидация бизнес-логики и интеграций** между публичными формами CMS, калькуляторами, Конфигуратором СИ, базой данных CRM, аналитикой поисковых запросов и личным кабинетом.

## 2. Архитектура и структура тестового комплекса

Тестовый комплекс платформы состоит из 5 взаимодополняющих уровней:

```
                  ┌──────────────────────────────────────────────┐
                  │          Мастер-раннер регрессии             │
                  │      `scripts/run_regression_suite.ts`       │
                  └──────────────────────┬───────────────────────┘
                                         │
        ┌────────────────────────────────┼────────────────────────────────┐
        ▼                                ▼                                ▼
 ┌───────────────┐              ┌──────────────────┐             ┌──────────────────┐
 │ Модульные     │              │ Комплексная      │             │ E2E UI и API     │
 │ тесты Vitest  │              │ регрессия и API  │             │ регрессия Cypress│
 │ (63 теста)    │              │ (22 проверки)    │             │ (3 сценария)     │
 └───────────────┘              └──────────────────┘             └──────────────────┘
```

## 3. Регламент и способы запуска тестирования

### 3.1. Запуск всех тестов в 1 команду (Основной сценарий)

Для проведения полного сквозного регрессионного тестирования системы и автоматической генерации отчета выполните:

```bash
npm test
# или
npm run test:all
```

### 3.2. Дополнительные команды тестирования из `package.json`

| Команда | Что делает |
| :--- | :--- |
| **`npm test`** / **`npm run test:all`** | Запускает полный цикл сквозного регрессионного тестирования (85 проверок) и обновляет отчёт `docs/testing/TEST_REPORT.md`. |
| **`npm run seo:audit`** | Запускает комплексный автоматический аудит метаданных, canonical и OpenGraph/Twitter Cards для 185 страниц. |
| **`npm run test:unit`** | Запускает 63 модульных и компонентных теста Vitest. |
| **`npm run test:integration`** | Запускает изолированное интеграционное тестирование СУБД CRM/CMS. |
| **`npm run test:e2e`** | Запускает headless-прогон E2E сценариев Cypress. |
| **`npm run lint`** | Выполняет строгую проверку типов TypeScript (`tsc --noEmit`). |

## 4. Матрица покрываемых сценариев (Test Matrix - 84 проверки)

### 4.1. Мониторинг бэкенда и безопасность
- **Health Check (`GET /api/health`)**: проверка работоспособности сервера Express (статус `200 OK`, JSON `{ status: 'ok' }`).
- **DB Health Check (`GET /api/db-health`)**: проверка активного пула подключений к PostgreSQL 17.
- **CSRF Token Generation (`GET /api/csrf-token`)**: выдача криптографического 64-символьного токена.
- **CSRF Protection Guard**: проверка блокировки модифицирующих запросов (POST, PUT, DELETE) без токена (возврат кода `403 Forbidden`).

### 4.2. База данных и хранилище CMS
- **Глобальное состояние CMS (`GET /api/cms/state`)**: чтение текущей структуры страниц, меню и каталогов.
- **Ключевой магазин данных (`GET/POST /api/cms/store/:key`)**: сохранение и считывание динамических настроек.
- **Страницы сайта (`POST /api/cms/pages`)**: создание кастомных страниц, проверка URL-алиасов и блоков.
- **Каталог оборудования (`GET/POST /api/equipment`)**: добавление новых моделей КИМ/сканеров с проверкой характеристик.

### 4.3. База данных CRM
- **Компании-контрагенты (`POST /api/crm/companies`)**: создание карточки завода, фильтрация и поиск.
- **Контакты ЛПР (`POST /api/crm/contacts`)**: привязка руководителей ОТК и главных метрологов.
- **Сделки и воронка продаж (`POST/PATCH /api/crm/deals`)**: прохождение этапов от первичного контакта до отгрузки.
- **Задачи инженеров (`POST /api/crm/tasks`)**: постановка задач с чек-листами и датами исполнения.

### 4.4. Документооборот и Лицензирование
- **Генерация ТКП (`POST /api/crm/proposals`)**: считывание спецификаций и создание предложений.
- **Договоры поставки (`POST /api/crm/contracts`)**: фиксация сумм, сроков и этапов оплаты.
- **Лицензии ПО TopSolid 7 (`POST /api/crm/licenses`)**: привязка программных ключей и статусов подписки.
- **Сертификаты обучений (`POST /api/crm/certificates`)**: выдача свидетельств операторам КИМ.
- **Сегментация клиентов (`POST /api/crm/client-lists`)**: создание целевых списков предприятий.

### 4.5. Сквозная интеграция CMS ➔ CRM
- **Публичные формы заявки (`POST /api/service-requests`)**: автоматическая конвертация заявки из калькуляторов в лид CRM.
- **Запрос ТКП из каталога (`POST /api/rfq`)**: передача запроса в RFQ-пул менеджеров.
- **Тикеты B2B-портала (`POST /api/b2b/tickets`)**: регистрация обращений в CRM Service Desk.
- **Онлайн-инженер (`POST /api/chat/session`)**: создание сессии чата и лида в CRM.
- **База знаний ГОСТ (`POST /api/knowledge-base`)**: проверка публикаций методик поверки.

## 5. Формат отчетов о тестировании (Test Reports)

После каждого запуска команды `npm test` система автоматически генерирует два артефакта:

1. **`docs/TEST_REPORT.md`** — форматированный документ в формате Markdown с понятной сводкой для инженеров, QA и руководства:
   - Статус прохождения (PASSED / FAILED);
   - Точная дата и время проведения;
   - Сводная таблица метрик и времени выполнения;
   - Подробный чек-лист всех сценариев с галочками `[x]`.

2. **`data/last_test_report.json`** — машиночитаемый структурированный JSON-файл для CI/CD систем и мониторинга:
   ```json
   {
     "timestamp": "2026-10-02T07:15:39.000Z",
     "environment": "Development Preview / Production Stand",
     "appVersion": "v2.9.253-PROD",
     "totalTests": 84,
     "passed": 84,
     "failed": 0,
     "durationMs": 25,
     "typeCheckStatus": "passed"
   }
   ```

## 6. Регламент проведения тестирования при доработках

1. **Перед внесением изменений:** Убедитесь, что исходный прогон `npm test` и `npm run test:unit` проходит без ошибок.
2. **В процессе разработки:** Напишите или отредактируйте код в соответствии с задачами.
3. **После завершения работ:** Запустите `npm test`. Мастер-раннер проверит типы, выполнит все тесты и сформирует свежий отчет `docs/TEST_REPORT.md`.
4. **При обновлении версии:** Актуализируйте номер версии в `docs/SITE_PASSPORT.md` и внесенные изменения в `docs/CHANGELOG.md`.
